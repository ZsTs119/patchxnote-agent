# Agent V1 MVP Implementation Plan

**Goal:** Build the smallest runnable PatchNote Agent that can be installed, log in with an agent-only read session, serve a local stdio MCP server, and expose safe read-only PatchNote account tools.

**Architecture:** Keep the Agent as a local Go binary plus an npm installer wrapper. MCP runs locally over stdio. PatchNote Go Server remains the source of truth and gets only additive agent auth/read projection changes so existing App/PC flows stay unchanged.

**Tech Stack:** Go, Cobra, Viper, OS-native keychain storage, PatchNote Go Server APIs, local stdio MCP, npm installer wrapper.

**Execution Rule:** Work sequentially in the primary agent. Do not use sub-agents or parallel task execution. Keep each step small, testable, and easy to revert.

---

## V1 Product Scope

V1 must close this user flow:

```text
npx -y @patchnote/agent install
patchnote login
patchnote auth status
patchnote mcp serve
Agent client calls read-only PatchNote MCP tools
patchnote logout
```

V1 MCP tools:

- `patchnote_get_current_user`
- `patchnote_list_recorder_cards`
- `patchnote_get_quota_summary`
- `patchnote_get_model_usage_summary`
- `patchnote_list_memories`
- `patchnote_search_memories`
- `patchnote_get_memory`

`patchnote_search_memories` may use local search over authorized cached projections in V1. Do not require GoServer full-text search for the first closed loop unless the server already has a safe read projection that can be reused without broadening App/PC contracts.

V1 does not include:

- recorder-card battery, live BLE state, storage, or recording status
- hardware bind, release, recover, reset, or format
- SK/credential read/write
- raw audio download
- complete raw or corrected transcript access
- model-run execution
- quota purchase, reward claim, or payment
- delete/update content
- Admin APIs
- background sync workers
- multi-account or workspace management

## GoServer Bypass Safety Rules

Agent support is a sidecar path. It must not become a third App/PC platform and must not loosen existing client handlers.

Hard rules:

- Do not add `agent` to `identity.Platform`.
- Do not insert agent rows into `client_installation`.
- Do not call or wrap `POST /v1/installations` or `POST /v1/installations/replacements` from Agent login.
- Do not let agent tokens parse as normal `clientaccess.Actor` tokens.
- Do not make existing App/PC write handlers accept agent actors.
- Do not route Agent through hardware connect/release, model execute, quota claim, payment, content delete, namespace clear, or Admin handlers.
- Do expose V1 Agent data through a small `/v1/agent/...` read-only projection surface.
- Do require explicit content platform selection and matching scope for `mobile` or `desktop` structured results.
- Do keep hardware projection narrower than App/PC hardware list; mask full MAC by default and never return SK/credential.
- Do prove old App/PC mobile/desktop login, replacement, refresh, logout, hardware, quota, model, and content flows are unchanged.

## Definition Of Done

- a fresh user can install the CLI through the npm wrapper
- `patchnote version` prints version/build metadata
- `patchnote login` completes against a development PatchNote server using phone OTP
- agent login does not create, replace, or revoke mobile/desktop installations
- GoServer does not create `PlatformAgent` or agent `client_installation` rows
- Agent tokens are rejected by existing App/PC write handlers
- V1 Agent server APIs live behind dedicated read-only `/v1/agent/...` routes
- structured-result access is explicitly scoped to either `mobile` or `desktop`
- credentials are stored through secure storage, not MCP config files
- `patchnote auth status` shows the current account projection
- `patchnote logout` revokes/removes local agent credentials
- `patchnote mcp serve` speaks stdio MCP without non-JSON logs on stdout
- MCP tool listing exposes only the seven V1 tools
- every V1 tool has schema validation, bounded output, stable errors, and read-only scope checks
- old App/PC login and read flows still pass regression tests
- docs explain install, login, MCP config, troubleshooting, and V1 limitations

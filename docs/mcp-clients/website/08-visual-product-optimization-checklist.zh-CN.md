## P0. 安装失败与回退边界

- [ ] 客户端未安装时，一键安装按钮要给出清楚回退：下载客户端、复制 AI 安装提示、复制命令、手动配置。
- [ ] 浏览器拦截自定义协议、用户取消“打开客户端”、系统没有协议关联时，页面不能卡死，要保留复制命令入口。
- [ ] 本机没有 Node.js / npm / npx 时，详情页要提示先安装 Node，或引导使用后续独立二进制安装方式。
- [ ] `npx` 首次下载慢、公司网络拦截 npm、代理配置缺失时，要给用户可理解的失败说明和重试路径。
- [ ] 现有 MCP 配置里已经有 `patchxnote` 同名 server 时，setup 必须合并或提示覆盖风险，官网文案不能暗示无脑覆盖。
- [ ] 用户选择 workspace/project 级配置还是 user/global 级配置时，详情页要说明影响范围。
- [ ] VS Code Remote、WSL、Dev Container、SSH remote 场景下，必须提示在哪个运行时使用 MCP，就在哪个运行时安装和登录。
- [ ] 客户端要求重启、刷新 MCP server、切换 Agent Mode、确认 trust prompt 时，详情页要作为验证步骤展示。
- [ ] 一键安装、AI assisted、命令安装、手动配置四条路径必须共享同一套最终验证口径：能看到 PatchXNote 工具名，并能调用一个只读工具。

## P0. 登录授权异常边界

- [ ] 未登录进入 `/v1/agent/oauth/authorize` 时展示手机号登录页，登录成功后回到原授权请求，不丢失 `client_id`、`state`、`redirect_uri` 等上下文。
- [ ] 已登录用户进入授权页时跳过手机号输入，直接进入授权确认。
- [ ] 手机号格式错误、验证码错误、验证码过期、验证码发送频率限制、网络失败、服务端错误都要有明确错误文案。
- [ ] 验证码发送按钮需要倒计时、重复点击保护和加载态。
- [ ] 用户刷新授权页、浏览器返回、重复提交授权时，不能产生重复授权或错误成功提示。
- [ ] 用户取消授权、授权请求过期、`state` mismatch、`redirect_uri` 不合法时进入统一失败页，并提供重新开始路径。
- [ ] 本地 callback 不可达、端口被占用、防火墙拦截、CLI 已退出时，官网成功页不能声称“已安装成功”，只能说明授权信息已返回或需要回到本机检查。
- [ ] 云平台 remote MCP 不走本地 callback，要单独展示平台 OAuth / connector session 的成功、失败和撤销入口。

## P0. 用户真实环境保护

- [ ] Cursor、VS Code 真实验收前先使用测试 profile、测试 workspace，或在用户确认后备份原配置文件。
- [ ] 任何自动写配置动作都必须记录被修改的文件路径和 server 名称，并提供撤销/卸载说明。
- [ ] 验收截图和日志禁止包含手机号、验证码、token、OAuth code、refresh token、完整本地路径、完整用户数据。
- [ ] 测试真实客户端时，不把用户现有 MCP server、编辑器设置、企业策略当成可删除或可覆盖对象。
- [ ] 如果客户端由企业策略禁用 MCP、禁用自定义协议或禁用外部工具调用，官网要展示为环境限制，不误判为 PatchXNote 安装失败。

## P0. 数据、状态与 schema 防错

- [ ] `web/mcp/data/clients.json` 必须通过 schema 校验；缺少 `id`、`name`、`category`、`evidence_state`、`primary_action` 的记录不上线。
- [ ] `primary_action=one_click` 时必须同时存在已验收 evidence；否则构建或校验失败。
- [ ] `category=cloud-platform` 时不能把本地 `npx` 作为主动作。
- [ ] 每个客户端的配置格式必须按官方实际格式输出：VS Code 不套用通用 `mcpServers`，Zed 不套用通用 `mcpServers`，Codex 不套用 JSON 当主配置。
- [ ] 图标缺失时页面可以降级为自有抽象占位，但必须显示为待补资产，不能继续使用文字首字母冒充正式图标。
- [ ] 页面渲染客户端名称、来源链接、错误信息和配置片段时要避免 XSS；动态文本优先用 `textContent`，代码块内容不拼未转义 HTML。
- [ ] 数据快照要记录来源日期和生成时间，防止官网展示过期官方文档状态。

## P0. 部署与路由边界

- [ ] GoServer 需要同时验证直接访问、刷新、深链进入详情页、深链进入授权成功/失败页，不只验证首页加载。
- [ ] 生产或测试环境如果存在 `/patchnote-test-api` 这类反向代理前缀，CSS、JS、图片、JSON 和内部跳转都必须正确加载。
- [ ] `/mcp`、`/mcp/`、`/mcp/clients/{id}`、`/mcp/platforms/{id}`、`/mcp/auth/success`、`/mcp/auth/error` 的 trailing slash 行为要一致。
- [ ] 静态资源 404、数据 JSON 加载失败、图片加载失败时要有可读降级，不出现空白页。
- [ ] index/data 使用短缓存或 no-store，图片等 assets 可以版本化长缓存；发布后不能让旧 JSON 配新 JS。
- [ ] 页面 title、description、canonical、基础 OG 图要补齐，分享链接不能显示临时标题或空白预览。
